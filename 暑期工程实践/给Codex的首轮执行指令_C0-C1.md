五、执行阶段 C1：工程骨架、配置、数据注册和冻结划分

按照实施计划建立模块化目录。实际命名可以根据现有工程做小幅调整，但至少应包含：

- configs：基准、数据集和运行配置；
- src：数据注册、划分、配置校验、manifest 和公共工具；
- tests：单元测试和最小集成测试；
- data/raw、data/processed、data/splits：原始数据、规范化数据和冻结划分；
- artifacts 或 outputs：后续模型与结果目录，本轮不得产生正式模型；
- reports：数据卡、审计和阶段报告。

具体完成以下任务：

1. 建立基准总配置，固定并校验：
   - 数据集：Adult、Default of Credit Card Clients；
   - 正式种子：2026、2027、2028、2029、2030；
   - 真实数据划分：R_source_train=60%、R_detector_train=15%、R_detector_val=10%、R_final_test=15%；
   - 污染率：0%、5%、10%、25%、50%、75%、100%；
   - 比例估计 bag_size=1000、calibration_bags=50、test_bags=100；
   - Track A 生成器名称：GaussianCopula、CTGAN、TVAE，但本轮只注册名称，不训练。
2. 对配置实施 schema 校验。非法比例、重复种子、未知分区、未知数据集或污染率越界必须明确报错。
3. 为两个数据集建立 registry，记录规范名称、来源、下载/本地位置、目标列、任务类型、类别列、数值列、缺失值规则、行数、列数、许可、获取日期和 SHA-256。
4. 建立确定性的稳定 row_id。row_id 必须不依赖 DataFrame 当前行号；重新读取同一原始数据后应保持一致。若存在完全重复行，应使用确定性副序号避免 ID 冲突，并在数据卡中报告重复情况。
5. 对两个数据集建立冻结划分：
   - 按目标标签分层；
   - 使用正式种子生成可复建的划分索引；
   - 保存 row_id 到 split 的映射，而不是只保存临时行号；

   - 对每个种子检查四个分区两两不重叠且并集等于可用样本全集。
6. 明确 target 与特征隔离，确保 row_id、split、数据来源等元数据不会意外成为模型特征。
7. 为 Adult 和 Credit 分别生成数据卡，至少展示：来源、许可、校验值、任务、样本量、数值/类别列、目标分布、缺失情况、重复行、各分区样本量和比例、各分区目标分布、已知风险。
8. 建立 run manifest 基础结构，至少预留并校验：run_id、时间、代码版本/状态、配置快照、数据校验值、数据集、协议、算法、生成器、种子、输入产物、输出产物、环境信息。run_id 应可追踪且不得静默覆盖已有运行。
