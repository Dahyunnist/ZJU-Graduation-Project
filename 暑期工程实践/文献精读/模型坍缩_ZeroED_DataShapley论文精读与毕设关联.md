# 第一篇：AI models collapse when trained on recursively generated data

## 1. 基本信息

正式引用：

> Shumailov, I., Shumaylov, Z., Zhao, Y., Papernot, N., Anderson, R., Gal, Y.  
> **AI models collapse when trained on recursively generated data**.  
> Nature 631, 755-759, 2024.  
> DOI: https://doi.org/10.1038/s41586-024-07566-y

这是一篇 Nature 论文，讨论生成式 AI 时代一个很重要的问题：

> 如果未来互联网上充满 AI 生成内容，而下一代模型又继续用这些内容训练，会发生什么？

论文的回答是：可能发生 **model collapse（模型坍缩）**。

---

## 2. 论文核心问题

过去的大模型大多训练在人类生成的数据上，例如：

- 人写的网页。
- 真实论坛讨论。
- 人类创作的书籍。
- 真实图像和说明。

但现在 AI 生成内容越来越多。未来训练数据中很可能混入大量模型生成内容。

论文关心的是：

> 当第 1 代模型用真实数据训练，第 2 代模型用第 1 代模型生成的数据训练，第 3 代模型又用第 2 代模型生成的数据训练，如此递归下去，模型会不会越来越差？

论文发现：会。并且这种退化不是偶然现象，而是生成模型递归训练中普遍存在的风险。

---

## 3. 什么是模型坍缩

论文给出的定义可以用大白话理解为：

> 模型坍缩是指生成模型反复使用前代模型生成的数据训练后，逐渐忘记真实数据分布，尤其先丢失低概率、长尾、少数群体的信息，最后生成结果变得越来越窄、越来越单一。

### 3.1 早期坍缩

早期坍缩表现为：

- 分布尾部消失。
- 少见事件被忽略。
- 少数群体信息减少。
- 模型生成内容越来越“平均”。

例如真实数据中有 1% 的罕见职业、罕见疾病、罕见收入组合。模型生成数据时可能没有采到它们。下一代模型继续训练，就更难恢复这些罕见模式。

### 3.2 后期坍缩

后期坍缩表现为：

- 方差越来越小。
- 样本越来越相似。
- 模型输出集中到少数模式。
- 最后与原始真实分布差距很大。

这就像不断复印一张图片，每一代都丢一点细节，最后图像变糊、变形。

---

## 4. 模型坍缩为什么会发生

论文总结了三类误差。

### 4.1 Statistical approximation error：统计近似误差

真实世界的数据分布是无限复杂的，但我们训练模型时只能采有限样本。

如果某个事件本来就很少见，那么有限采样时很可能采不到。采不到，就无法被下一代模型学习。

对你的毕设来说，这点很重要：

> 合成表格数据可能天然削弱少数类别和长尾组合。

例如金融数据中的少数违约人群、医疗数据中的罕见病人群，都可能在合成过程中被淡化。

### 4.2 Functional expressivity error：函数表达能力误差

模型能力有限，不能完美表达真实分布。

例如真实分布是两个复杂人群混合，但模型只能学成一个简单分布，就会丢失结构。

在表格数据中，这可能表现为：

- 学不准变量之间的复杂相关性。
- 学不准多峰分布。
- 学不准少数类别。

### 4.3 Functional approximation error：函数优化误差

即使模型理论上能表达真实分布，实际训练过程也可能学不到。

例如：

- 优化算法有偏差。
- 训练不充分。
- 损失函数不完全符合目标。
- 模型容易过拟合某些模式。

这也说明，合成数据生成器即使很先进，也不可能保证完美复制真实数据分布。

---

## 5. 论文用了哪些实验

论文从三个层面说明模型坍缩：

1. 离散分布的理论分析。
2. 高斯分布 / GMM / VAE 等较简单生成模型。
3. 语言模型 OPT-125M 在 WikiText-2 上的递归微调实验。

### 5.1 离散分布理论

论文说明：即使假设模型能完美学习当前样本分布，只要每一代都要重新采样，低概率事件就有概率消失。

一旦消失，下一代就更难恢复。

### 5.2 高斯模型坍缩

论文证明，在某些高斯近似场景中，递归训练会导致：

- 估计分布与原始分布距离越来越大。
- 方差趋近于 0。

这就是“越来越集中、越来越单一”。

### 5.3 语言模型实验

论文用 OPT-125M 在 WikiText-2 数据集上做实验：

1. 第 0 代模型用真实文本训练。
2. 第 1 代模型用第 0 代生成的文本训练。
3. 第 2 代模型用第 1 代生成的文本训练。
4. 继续递归。

实验中模型的 perplexity 和生成文本质量逐代恶化，后代模型会出现重复、跑题、语义混乱等现象。

# 第二篇：ZeroED

## 8. 基本信息

正式引用：

> Wei Ni, Kaihang Zhang, Xiaoye Miao, Xiangyu Zhao, Yangyang Wu, Yaoshu Wang, Jianwei Yin.  
> **ZeroED: Hybrid Zero-Shot Error Detection Through Large Language Model Reasoning**.  
> ICDE 2025.  
> DOI: https://doi.org/10.1109/icde65448.2025.00234  
> arXiv: https://arxiv.org/html/2504.05345v1  
> GitHub: https://github.com/WelkinNi/ZeroED

这篇论文是组内工作，研究的是：

> 如何用大语言模型帮助检测表格数据中的错误。

它不是检测“合成数据”，而是检测“脏数据 / 错误单元格”。但它的方法范式和你的 LLM 赋能合成检测高度相关。

---

## 9. ZeroED 想解决什么问题

表格错误检测是数据清洗中的第一步。

表格错误可能包括：

- 缺失值。
- 拼写错误。
- 格式错误。
- 离群值。
- 违反跨列规则的值。

例如：

| Name | Gender | Education | Salary |
|---|---|---|---:|
| Alice | F | Bachelor | 8000 |
| DaveGreen | F | Bechxlor | 6000 |

其中可能存在：

- `Bechxlor` 是拼写错误。
- `DaveGreen` 可能违反姓名格式。
- `Salary=6000` 可能是离群值。
- `Name` 和 `Gender` 之间可能存在规则冲突。

传统方法有两个问题：

1. 人工规则方法需要专家手写规则。
2. 机器学习方法需要大量人工标注。

LLM 看起来能减少人工成本，但如果直接问：

```text
这条记录有没有错误？
```

效果有限，而且对大表逐条询问成本很高。

ZeroED 的目标就是：

> 用 LLM 的推理能力减少人工规则和人工标注，同时避免直接让 LLM 处理全量数据造成高成本。

---

## 10. ZeroED 的总体框架

ZeroED 是一个 hybrid framework，也就是“LLM + 传统机器学习”的混合框架。

它不是让 LLM 直接判断所有数据，而是让 LLM 参与几个关键环节，再训练一个普通分类器完成大规模检测。

整体分四步：

1. 特征表示。
2. 代表性数据采样与 LLM 标注。
3. 训练数据构建。
4. 训练检测器并预测。

---

## 11. 第一步：LLM 增强的特征表示

传统错误检测常用简单特征：

- 值出现频率。
- 字符模式。
- TF-IDF。
- 统计异常程度。

这些特征只能看到表层信息，不理解错误原因。

ZeroED 增加了三类信息：

### 11.1 统计特征

例如：

- 某个值在该列出现多少次。
- 某种字符模式出现多少次。
- 某个值和其他列值共同出现的频率。

### 11.2 语义特征

使用 FastText 等预训练 embedding，把单元格值转成语义向量。

例如 `Bachelor` 和 `Master` 在语义空间中可能比 `Bachelor` 和 `6000` 更接近。

### 11.3 LLM 生成的错误原因感知特征

这是 ZeroED 的关键。

ZeroED 会让 LLM 根据数据样例和字段含义生成可执行的检查规则，例如 Python 函数：

```python
def check_salary(value):
    return value > 0 and value < 1000000
```

或者跨列检查：

```python
def check_arrival_departure(row):
    return row["arrival_time"] >= row["departure_time"]
```

然后把这些规则执行结果变成二值特征。

这点对你的毕设非常有启发：

> LLM 不一定只负责最终判断，也可以负责生成特征、规则、解释和标注。

---

## 12. 第二步：代表性采样与 LLM 标注

直接让 LLM 标注全表太贵。

ZeroED 的做法是：

1. 先用特征把数据聚类。
2. 每个簇选代表性样本。
3. 只让 LLM 标注这些代表样本。

这能显著降低 token 成本。

论文中还设计了检测指南生成流程：

- 先让 LLM 生成数据分析函数。
- 用函数分析全表分布。
- 再让 LLM 基于分析结果生成每个属性的错误检测指南。
- 最后让 LLM 根据指南标注代表样本。

这比简单 prompt 更强，因为 LLM 获得了更完整的数据上下文。

---

## 13. 第三步：训练数据构建

LLM 标注的样本数量有限，不能直接训练强检测器。

ZeroED 做了三件事：

### 13.1 簇内标签传播

同一聚类中的样本往往相似，因此可以把代表样本的标签传播给同簇样本。

### 13.2 互相验证

标签传播可能有错。ZeroED 用 LLM 生成/优化的检查规则和传播标签互相验证，过滤不可靠数据。

### 13.3 LLM 错误增强

错误样本通常少。ZeroED 让 LLM 生成更多语义合理的错误样例，缓解类别不平衡。

---

## 14. 第四步：训练普通分类器

最后 ZeroED 用构建好的训练数据训练一个 MLP 分类器，判断单元格是否错误。

这说明 ZeroED 的思想不是“LLM 取代机器学习”，而是：

> LLM 负责提供高质量推理、规则和少量标注，机器学习负责低成本、大规模预测。

---

## 15. ZeroED 的实验结论

论文在 7 个数据集上实验，包括 Hospital、Flights、Beers、Rayyan、Billionaire、Movies、Tax。

比较方法包括：

- dBoost。
- Nadeef。
- Katara。
- ActiveClean。
- Raha。
- FM_ED。

主要结论：

- ZeroED 在多个数据集上取得更高 F1。
- 相比传统规则方法，ZeroED 更全面。
- 相比纯 LLM prompt 方法，ZeroED 更省 token、更稳定。
- 消融实验显示 guideline generation、criteria reasoning、correlated attributes 都有贡献。
- 大模型通常比小模型效果好，Qwen2.5-72B 表现较强。
- 聚类采样优于随机采样。

---

## 16. ZeroED 和你的毕设有什么关系

你的毕设中方法④是：

> LLM 赋能检测合成表格数据。

ZeroED 正是最直接的参考。

不过你要检测的不是“错误单元格”，而是“合成记录 / 合成污染”。因此可以借鉴但不能照搬。

### 16.1 可以借鉴的地方

#### 1. 表格序列化

ZeroED 把表格 tuple 转成文本：

```text
{age: 39, education: Bachelor, occupation: Sales, income: <=50K}
```

你也可以这样把一条记录输入给 LLM。

#### 2. schema + 示例 + 待测记录

ZeroED 强调上下文和指南。你可以设计 prompt：

```text
你是数据质量专家。
下面是 Adult 数据集 schema。
下面是若干真实记录。
请判断待测记录是否可能为合成数据。
```

#### 3. 代表性采样降低成本

如果你要让 LLM 检测大量记录，可以先聚类或抽样，只让 LLM 标注代表记录，再训练分类器。

这与 ZeroED 的 hybrid 思路一致。

#### 4. LLM 生成可解释理由

你可以要求 LLM 输出：

```json
{
  "label": "synthetic",
  "confidence": 0.83,
  "reasoning": "age, occupation and income combination is uncommon..."
}
```

这能让你的 LLM 检测方法更可解释。

### 16.2 需要改造的地方

ZeroED 检测的是 cell-level error。

你的任务更偏 record-level / corpus-level synthetic detection。

因此：

- ZeroED 的单元格错误标签不能直接用。
- 你的标签是 real/synthetic。
- 你的检测对象是一整条记录，而不一定是某个单元格。
- 你的关注点是“过于规则、不像真实、分布偏差、组合异常”，而不是拼写或格式错误。

---

## 17. 综述中如何写 ZeroED

短版可以这样写：

> Ni 等人提出的 ZeroED 是一种面向表格数据错误检测的混合式零样本框架，将 LLM 推理能力与传统机器学习检测流程结合起来。该方法通过 LLM 生成错误原因感知特征和检测指南，仅对聚类选出的代表性样本进行 LLM 标注，再通过标签传播、错误增强和验证机制构建训练数据，最终训练分类器完成大规模错误检测。ZeroED 表明，LLM 不仅可以直接给出判断，还可以作为表格数据治理流程中的规则生成器、标注器和语义增强器。本文借鉴这一范式，将 LLM 从表格错误检测扩展到合成表格数据污染检测，用于判断记录是否具有机器生成痕迹。

# 第三篇：Data Shapley

## 18. 基本信息

正式引用：

> Amirata Ghorbani, James Zou.  
> **Data Shapley: Equitable Valuation of Data for Machine Learning**.  
> ICML 2019, PMLR 97:2242-2251.  
> PDF: https://proceedings.mlr.press/v97/ghorbani19c/ghorbani19c.pdf

这篇论文研究的是：

> 如何公平地衡量每一条训练数据对机器学习模型性能的贡献。

---

## 19. Data Shapley 想解决什么问题

在机器学习中，数据很值钱，但问题是：

> 一条具体的数据到底值多少钱？它对模型性能贡献有多大？

例如你有 1000 个病人的数据，用它们训练心脏病预测模型。你可能想知道：

- 哪些病人的数据最有价值？
- 哪些数据几乎没贡献？
- 哪些数据甚至是有害的？
- 如果要继续收集数据，应该收集哪类数据？

传统方法常用 leave-one-out：

> 把某条数据拿掉，重新训练模型，看性能下降多少。

但 leave-one-out 有缺陷。

例如每条数据都有一个一模一样的副本，拿掉其中一条不会影响模型，因为副本还在。leave-one-out 会认为每条数据价值都是 0，但这显然不合理。

Data Shapley 就是为了解决这种“数据之间有交互贡献”的问题。

---

## 20. Data Shapley 的基本思想

Data Shapley 借鉴合作博弈中的 Shapley value。

你可以把每条训练数据看成一个玩家：

```text
玩家 = 训练数据点
合作结果 = 模型在测试集上的性能
```

某条数据的价值不是只看它单独有没有用，而是看：

> 它加入各种不同数据子集时，平均能带来多少性能提升。

换句话说，Data Shapley 计算的是一条数据的平均边际贡献。

---

## 21. 三个公平性性质

论文认为合理的数据估值应该满足三个性质。

### 21.1 无贡献则无价值

如果一条数据加入任何训练子集都不会改变性能，那么它价值为 0。

### 21.2 贡献相同则价值相同

如果两条数据在任何情况下带来的性能变化都一样，那么它们应该有相同价值。

### 21.3 可加性

如果总任务由多个子任务组成，一条数据对总任务的价值应等于它对各子任务价值之和。

论文证明，满足这些性质的数据估值形式就是 Shapley value。

---

## 22. 为什么精确计算很难

如果有 n 条数据，所有数据子集数量是指数级的。

精确 Data Shapley 需要遍历大量子集，并对每个子集重新训练模型，计算成本极高。

所以论文提出近似方法。

---

## 23. 论文提出的近似方法

### 23.1 Monte Carlo Shapley

随机打乱数据顺序，逐个加入数据，记录每条数据加入时带来的性能提升。

重复很多次，取平均。

直觉：

```text
在很多种随机加入顺序下，一条数据平均能带来多少提升？
```

### 23.2 Truncated Monte Carlo Shapley

当模型性能已经接近完整数据集性能时，后面再加数据的边际贡献通常很小。

因此可以提前停止后续计算，节省时间。

### 23.3 Gradient Shapley

对神经网络等复杂模型，反复完整训练太贵。论文提出基于梯度更新的近似方法，用一次训练过程中的性能变化估计数据贡献。

### 23.4 Group Shapley

如果数据太多，可以不算每条记录，而是算一组数据的价值。

例如按性别、年龄、种族分组，计算某个群体数据的价值。

这对你的毕设尤其有用，因为你可以计算：

- 真实数据组的价值。
- 合成数据组的价值。
- 不同污染比例下数据组的价值变化。

## 24. 论文实验结论

论文展示了 Data Shapley 的多个用途。

### 24.1 找出高价值数据

移除高 Shapley 值的数据，模型性能下降明显。

这说明高 Shapley 数据确实对模型重要。

### 24.2 找出低价值或负价值数据

移除低 Shapley 值的数据，有时模型性能反而提升。

这说明低价值数据可能是噪声、异常点或有害样本。

### 24.3 识别错误标签和腐坏数据

论文发现：

- 标签翻转的数据往往有低 Shapley 值。
- 加噪声的图片 Shapley 值更低。

这对你的毕设有启发：

> 如果合成数据损害下游模型，它们可能表现为低 Shapley 或负 Shapley 数据。

### 24.4 指导数据采集

收集与高价值数据相似的新数据，比随机收集更能提升模型性能。

## 26. 你可以怎么设计估值实验

### 26.1 最简单版本

先不要直接算完整 Shapley。

可以定义：

```text
V(D) = 用数据集 D 训练模型后，在真实测试集上的 AUROC 或 F1
```

然后比较：

```text
ΔV(p) = V(D_mixed(p)) - V(D_real)
```

这就是说明书中的估值偏差。

### 26.2 Shapley 版本

如果时间允许，可以进一步：

1. 构造真实 + 合成混合训练集。
2. 对训练记录计算近似 Shapley 值。
3. 比较真实记录和合成记录的 Shapley 分布。
4. 看污染比例变化时 Shapley 分布如何变化。

例如：

| 数据类型 | 平均 Shapley |
|---|---:|
| 真实记录 | 0.0031 |
| CTGAN 合成记录 | 0.0012 |
| TVAE 合成记录 | 0.0017 |

如果合成记录平均贡献更低，说明它们对下游任务价值较弱。

### 26.3 对照实验很重要

要避免把“数据量增加”误认为“合成数据有效”。

应该比较：

- 加入 1000 条合成数据。
- 加入 1000 条真实数据。

两者差异才更接近“合成污染”的净效应。
