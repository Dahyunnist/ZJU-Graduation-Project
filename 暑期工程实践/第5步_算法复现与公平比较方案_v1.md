# 第5步：算法复现与公平比较方案 v1.0

> 本文件固定“复现哪些算法、按什么顺序、做到什么程度才算跑通”。数据和协议统一引用《第3步_固定基准规格_v1.md》。

## 1. “复现完成”的严格定义

一个算法只有同时满足以下条件，状态才能从`planned`改为`reproduced`：

1. 有论文出处、代码来源和许可记录；
2. 能在固定配置下从命令行完成训练、推理和指标计算；
3. 保存解析后的配置、环境、日志、模型、逐样本预测和汇总指标；
4. 至少在一个小规模论文设定中复核到相同方向的结果趋势；
5. 接入统一数据接口，未自行改变数据划分和测试样本；
6. 至少运行5个正式随机种子，或说明算法为何只有确定性单次结果；
7. 有README说明成功命令、预计资源、实际耗时和已知差异；
8. 单元测试和最小集成测试通过。

仅“仓库安装成功”“示例Notebook能运行”或“跑出一个数”不算复现完成。

## 2. 统一算法接口

### 2.1 样本检测器

```python
fit(train_records, train_labels, val_records=None, val_labels=None, **context)
predict_score(records, **context) -> np.ndarray  # 合成概率/分数，越大越像合成
save(path)
load(path)
```

所有检测器输出原始分数和校准后概率。阈值只允许在验证集选择。跨表模型可额外接收`table_id`，但最终测试标签不可见。

### 2.2 比例估计器

```python
fit(calibration_scores, calibration_labels, **context)
predict_prevalence(test_scores, **context) -> float  # 强制报告原始值与clip后值
```

所有量化器复用同一检测器分数；比较量化器时不能让某个方法单独更换底层分类器。正式主表至少分别基于C2ST-XGBoost和3-gram LR两组分数。

### 2.3 数据估值器

```python
fit_value_model(train_x, train_y, val_x, val_y, utility_fn, seed)
score_training_records() -> np.ndarray
```

价值评估的验证/测试数据必须为纯真实记录；不同估值器使用相同下游任务、相同效用函数和相同污染训练集。

## 3. 固定算法矩阵

### 3.1 任务线一：样本级检测

|ID|算法|角色|适用协议|优先级|完成要求|
|---|---|---|---|---|---|
|D-LR|C2ST-Logistic Regression / pMSE分类器|经典弱基线|P1；Track A|P0|修正现有代码，5种子|
|D-XGB|C2ST-XGBoost|经典强表格基线|P1、P2；Track A|P0|调参只用val，输出SHAP/PFI可选|
|D-3G|Character 3-gram + LR|直接论文跨表基线|P1–P4；Track B|P0|随机列置换、`<column>:<value>`、字符3gram|
|D-FT|Flat-text character Transformer|直接论文基线|P1–P4|P1|从字符级训练；保存tokenizer|
|D-TT|Table/column-wise Transformer|直接论文基线|P1–P4|P1|每表QuantileTransformer/OrdinalEncoder，跨表共享嵌入|
|D-DW|Datum-wise Transformer|AAAI 2026核心SOTA|P1–P4|P0重点|datum内有局部位置编码，row层无全局位置编码|
|D-DWTA|Datum-wise + table adaptation|AAAI 2026完整方法|P3–P5|P1|梯度反转+table分类头；与D-DW消融|
|D-XAI|XGBoost + PFI/TreeSHAP/PDP|解释模块|P1、P2|P2|只解释已通过伪影审计的模型|

其中P0表示必须首先完成，P1表示论文主结果需要，P2表示增强项。

### 3.2 任务线二：污染比例估计

|ID|算法|类别|优先级|关键实现检查|
|---|---|---|---|---|
|Q-CC|Classify and Count|硬计数|P0|阈值来自val|
|Q-PCC|Probabilistic CC|软计数|P0|平均校准概率|
|Q-ACC|Adjusted CC|混淆率校正|P0|分母接近0时记录失败，不静默吞掉|
|Q-PACC|Probabilistic ACC|软混淆率校正|P0|保存软TPR/FPR|
|Q-EMQ|EMQ/SLD|先验偏移EM|P0强基线|记录迭代、收敛和假设|
|Q-HDy|Hellinger Distance y|分布匹配经典|P0强基线|分箱敏感性固定|
|Q-DyS|DyS|混合分布匹配|P0强基线|固定距离、bins和搜索网格|
|Q-MS|Median Sweep|多阈值校正|P0|使用已修复版本并记录QuaPy版本|
|Q-KDEy|KDEy-ML|连续密度匹配|P1 SOTA|固定带宽/优化器；二分类主结果|
|Q-CS|Continuous Sweep|2026最新二分类量化|P1 SOTA|参数分布错设消融；与SLD/DyS对比|

实现优先使用QuaPy稳定版本，但必须用手写CC/PCC/ACC/PACC小样本结果交叉核验库调用，防止标签方向或参数含义错误。

### 3.3 任务线三：效用与数据估值

|ID|算法/分析|角色|优先级|完成要求|
|---|---|---|---|---|
|V-CURVE-LR|LR污染率—效用曲线|透明下游基线|P0|7比例×3生成器×2表×5种子|
|V-CURVE-XGB|XGBoost污染率—效用曲线|强下游模型|P0|与LR同数据、同测试集|
|V-KNN|KNN-Shapley|精确高效估值|P0|小N暴力Shapley核验；正式数据分批|
|V-OOB|Data-OOB|可扩展树模型估值|P0|保存OOB覆盖次数；与KNN排序相关性|
|V-TMC|TMC-Shapley|经典通用近似|P1|只在小数据子集运行；报告Monte Carlo误差|
|V-BZ|Data Banzhaf|稳健估值|P2|预算允许时比较随机训练稳定性|

模型崩塌、Collapse or Thrive和推断效用论文不作为估值算法排行项。它们只指导替换式/追加式对照和扩展影响分析。

## 4. 各算法复现细节

### 4.1 C2ST-LR与C2ST-XGBoost

1. 使用统一预处理：数值中位数填补+标准化；类别众数填补+OneHot；XGBoost可使用统一编码或其类别特征模式，但主结果固定一种。
2. 真实/合成训练集保持1:1；最终另外报告自然低污染下的AUPRC。
3. LR超参数候选固定为`C ∈ {0.01,0.1,1,10}`；XGBoost固定小型搜索空间并在val AUROC选择。
4. 输出AUROC、AUPRC、balanced accuracy、F1、TPR@5%FPR、ECE、Brier和效率。
5. 做标签置换sanity check：AUROC应接近0.5；若仍明显偏高，检查泄漏。

### 4.2 3-gram LR

1. 每条记录转换为若干`<column>:<value>`片段；数值格式、缺失值和布尔值统一规范化。
2. 每个epoch/样本使用固定随机种子打乱列顺序；测试同时报告原顺序和随机置换顺序。
3. 使用`TfidfVectorizer(analyzer='char', ngram_range=(3,3))`与LR；向量器只能拟合训练文本。
4. 记录词表大小、稀疏矩阵内存和未知3-gram比例。
5. 先在Adult P1核对，再跑B-small P3，最后B-full P1–P4。

### 4.3 Flat-text与Table Transformer

Flat-text按论文从字符级训练，避免用预训练LLM造成设定变化。固定最大长度并报告截断率。Table Transformer对每张表独立拟合QuantileTransformer和OrdinalEncoder，但数值/类别共享投影层，模型不能依赖固定列数。

二者先用B-small完成训练；若论文细节缺失，所有推断参数写入`reproduction_notes.md`，不得把自定细节写成论文原设定。

### 4.4 Datum-wise Transformer

最小论文对齐结构：

1. 单元格表示为`<column>:<value>`字符序列；
2. datum encoder使用字符embedding、datum内部局部位置编码和CLS-Datum；
3. 每行拼接所有CLS-Datum及CLS-Target；
4. row transformer不加入跨列全局位置编码，保证列置换不变；
5. CLS-Target进入二分类头；
6. BCE训练，早停依据跨表验证AUROC；
7. embedding维度优先对齐论文192；层数、head数和长度不足细节通过配置显式记录；
8. 强制测试：对同一行随机打乱列10次，预测分数最大差值应低于预设容差。

Table adaptation版本增加table分类头和gradient reversal。总损失中的适配权重使用论文cosine schedule；输出D-DW与D-DWTA成对消融。

### 4.5 比例估计

先冻结检测器，不在最终bags上更新任何模型。流程为：

`训练检测器 → 验证集概率校准 → 构建量化器校准分布 → 对最终bags估计比例`。

每种量化器输出原始估计和裁剪到[0,1]后的估计；主MAE使用裁剪值，越界率使用原始值。EMQ、HDy、DyS、Median Sweep、KDEy和Continuous Sweep必须记录核心假设，跨生成器结果按分布偏移类型解释。

### 4.6 KNN-Shapley与Data-OOB

KNN-Shapley先在`N≤12`的玩具数据上与全子集精确Shapley比较，再扩到正式数据；类别变量编码与距离度量固定。Data-OOB固定bagging弱学习器数量并报告每条记录被OOB评估的次数。

两种方法统一输出：

- 真实与合成价值箱线/小提琴图；
- 各来源均值、中位数、负价值比例；
- 删除最低价值5/10/20/30%后的真实测试性能；
- 价值排序跨种子Spearman；
- 价值作为来源分数的AUROC只作诊断，不将估值器包装成检测器主结果。

## 5. 公平比较约束

1. 同一协议下所有算法读取相同manifest和测试记录ID；
2. 同一算法不得因测试表不同而人工选择不同超参数，除非协议允许table adaptation；
3. 预处理器只拟合训练分区；
4. 概率校准、阈值选择、量化器拟合均只用val/calibration；
5. 测试集只运行一次逻辑由程序保证，调试使用单独smoke数据；
6. 底层检测器相同时才比较不同量化器；
7. 生成器质量指标与检测难度同时报告，防止把训练失败的生成器当作检测算法胜利；
8. 结果汇总按表宏平均，同时保留逐表结果和最差表；
9. 算法失败、OOM或不收敛也要形成记录，不能从平均值中无声删除；
10. 自实现与官方代码结果使用不同`implementation`字段。

## 6. 复现状态表

每个算法在`reports/reproduction_status.csv`中记录：

```text
algorithm_id,paper,code_url,commit,license,status,
install_ok,smoke_ok,benchmark_ok,paper_trend_ok,
last_run,config_path,run_ids,notes
```

状态枚举固定为：`planned / installing / smoke_passed / integrated / reproduced / blocked`。`blocked`必须写明已尝试内容和可行动的下一步。

## 7. 固定实施顺序

1. 修正D-LR并新增D-XGB，完成Track A Adult正式5种子结果；
2. 完成D-3G，在Adult P1和B-small P3跑通；
3. 用D-XGB分数实现Q-CC至Q-MS八个量化器，先完成Adult比例曲线；
4. 完成Track A两表×三生成器，并跑全部比例估计；
5. 实现D-FT和D-TT，跑B-small；
6. 实现D-DW并通过列置换不变性测试；
7. 实现D-DWTA，跑B-small P1–P4；
8. 扩到B-full十四表×四生成器，形成论文对齐结果；
9. 加入Q-KDEy和Q-CS；
10. 完成V-CURVE、V-KNN、V-OOB；最后再做V-TMC/V-BZ和XAI扩展。

这一次序保证每一阶段都有可交付结果，并避免在基础数据尚未固定时直接投入SOTA模型。
