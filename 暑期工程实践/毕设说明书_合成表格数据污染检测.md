## 1. 课题背景与意义

### 1.1 合成表格数据的崛起与风险

随着深度生成模型（CTGAN、TVAE、CopulaGAN 等）和大语言模型（LLM）的成熟，高质量合成表格数据的生成门槛大幅降低。合成数据在隐私保护、数据增强、测试数据生成等场景中应用广泛，但同时也带来了新的风险：**合成表格数据可能混入真实训练数据集，改变数据分布、引入虚假相关性、破坏变量间因果关系，进而导致下游模型性能退化或决策偏差。**

这一问题与"模型坍缩（model collapse）"在文本领域的研究遥相呼应：Shumailov 等（Nature 2024）证明，不加区分地用模型生成内容训练会使分布尾部逐代消失、不可逆退化。在表格数据场景，合成数据若与真实数据混合后用于下游模型训练，同样可能导致分布窄化、因果结构失真。因此，**在表格数据进入训练 / 分析管线前，识别并量化"合成污染"，是数据质量治理的一道新关口。**

### 1.2 与课题组主线的对接

本选题**横跨课题组三大研究方向**，是组内研究版图的交汇点：

**（1）不完整表格数据治理（组内特色基础）**

课题组在表格数据清洗、填充、错误检测与纠正方面有深厚积累：
- **TabClean**（JMLR MLOSS 投稿）：首个统一经典 / 深度生成 / LLM 方法的表格数据准备工具箱，覆盖填充、检测、纠正三大子任务。
- **ZeroED**（ICDE 2025）：基于 LLM 推理的零样本表格错误检测。
- 多视图最优传输填充（TKDE 2024）、自动数据修复（VLDB 2024）、不完整数据公平性（SIGIR 2025）等。

本选题将"合成数据检测"作为表格数据治理的新维度，天然衔接 TabClean 的检测模块。更进一步，**填充值本身就是一种"合成数据"**——研究填充与合成污染的边界，是组内填充方向的自然延伸。

**（2）LLM 赋能（贯穿性方向）**

课题组的核心范式是"用 LLM 推理能力做数据治理"：ZeroED 用 LLM 推理判别表格错误，ZeroEC 用 LLM 做错误纠正。本选题延续这一范式，将 LLM 从"合成数据生成器"扩展为"合成数据检测器"——用 LLM 的语义理解能力判别一条记录是否"过于规则 / 不像真实数据"。这是 ZeroED 范式从"检测错误"到"检测合成"的自然延伸。

本选题的"估值影响分析"模块直接连接这一方向：**如果数据集含有合成污染，它的价值如何变化？** 这为组内"因果忠实的数据定价"新方向提供实证基础。

## 2. 问题定义（形式化）

### 2.1 基本设定

设真实表格数据分布为 $D_{real}$，某合成数据生成器 $G$（如 CTGAN、TVAE 或 LLM）产生的合成表格数据分布为 $D_{syn}$。每个数据集包含 $d$ 个属性（混合数值型和类别型），每条记录 $x \in \mathbb{R}^d$。

### 2.2 三类任务

**任务一  样本级检测**

学习 / 构造打分函数 $s(x)$，使真实样本与合成样本得分可分。

- 输入：单条记录 $x$
- 输出：二分类标签 $\hat{y} \in \{real, syn\}$ 或连续分数 $s(x) \in [0, 1]$
- 评估指标：AUROC、TPR@FPR=5%、F1

**任务二  语料级污染比例估计**

给定混合语料 $C$（合成占比真值 $p$ 未知），输出估计 $\hat{p}$。

- 输入：混合数据集 $C = \{(x_i)\}_{i=1}^{n}$，其中 $p \times n$ 条来自 $D_{syn}$
- 输出：估计占比 $\hat{p} \in [0, 1]$
- 评估指标：$\text{MAE} = \frac{1}{K}\sum_{k=1}^{K}|\hat{p}_k - p_k|$，在多档真值上平均

**任务三  估值影响分析**

在不同污染比例 $p$ 下，测量合成数据对数据估值指标的影响。

- 输入：同一基础数据集在不同 $p$ 下的混合版本
- 输出：估值指标随 $p$ 变化的曲线
- 评估指标：
  - 估值偏差：$\Delta V(p) = V(D_{mixed}(p)) - V(D_{real})$，其中 $V$ 为估值函数
  - 下游效用变化：在 $D_{mixed}(p)$ 上训练下游模型，在真实测试集上评估性能变化

### 2.3 关键自变量（实验要系统变化的）

| 自变量 | 取值 | 实验目的 |
|--------|------|---------|
| 合成占比 $p$ | {0%, 5%, 10%, 25%, 50%, 75%, 100%} | 难度曲线，尤其关注低占比 5–10% |
| 生成器 $G$ | CTGAN、TVAE、LLM 生成（≥2 类） | 跨生成器泛化 |
| 生成方式 | 全生成（从零生成）、条件生成（给定部分属性） | 检测难度差异 |
| 数据领域 | ≥2 个（如医疗、金融、人口统计） | 跨领域泛化 |
| 下游任务 | 分类、回归 | 估值影响的任务依赖性 |

## 5. 阶段二：污染基准构建（约 6–8 周，全题的核心资产）

### 5.1 真实表格数据来源（$D_{real}$）

选 2–3 个领域，公开可得、许可清晰：

| 领域 | 数据集 | 特征类型 | 规模 |
|------|--------|---------|------|
| 人口统计 | UCI Adult | 类别 + 数值 | ~48K 行, 14 列 |
| 医疗健康 | UCI Heart Disease / Breast Cancer | 类别 + 数值 | ~300–700 行 |
| 金融信贷 | Default of Credit Card Clients / Lending Club | 类别 + 数值 | ~30K 行 |

- 每数据集取全量或子样本（如 5000–10000 行）；
- 记录数据卡：来源、许可、特征描述、缺失率、基本统计。

### 5.2 合成数据生成协议（$D_{syn}$，务必固定并记录）

**三类生成器各做一份，便于对比难度：**

| 类型 | 代表 | 生成原理 | 预期检测难度 |
|------|------|---------|------------|
| ① 深度生成—GAN | CTGAN | 条件 GAN，逐条生成 | 中 |
| ② 深度生成—VAE | TVAE | 变分自编码器 | 中 |
| ③ LLM 赋能生成 | 用 LLM 根据 schema + few-shot 生成记录 | 大模型语义生成 | 高（最像真实） |
| ④ 统计方法（baseline） | GaussianCopula | 高斯 Copula 拟合 | 低（最易检测） |

**生成器配置记录**：
- 模型版本、训练 epoch、生成条数、随机种子；
- LLM 生成的 prompt 模板、温度、top-p、few-shot 样本数。

**质量过滤**：
- 去重（合成数据内部去重、与真实数据的精确匹配检查）；
- 去无效（数值越界、类别值不在定义域内）；
- 去泄漏（合成数据中与真实数据完全一致的记录需移除）；
- 统计相似性检查：用 SDMetrics 确认合成数据与真实数据的统计距离在合理范围（不能太远 = 生成失败，也不能为零 = 泄漏）。

### 5.3 混合与划分（防数据泄漏是第一纪律）

**样本级标注集**：
- 每条记录标注"真实（0）/ 合成（1）"；
- 严格按"源数据集"划分 train / val / test：同一份真实数据及其对应的合成版本不可跨集出现。

**语料级混合集**：
- 按合成占比 $p \in \{0\%, 5\%, 10\%, 25\%, 50\%, 75\%, 100\%\}$ 构造混合数据集；
- 每档构造多个随机种子重复，取平均。

**专门泛化测试集**：
- 跨生成器：训练时只见 CTGAN 合成数据，测试时见 TVAE / LLM 合成数据；
- 跨领域：训练时用 Adult，测试时用 Credit。

**交付**：
- 基准以脚本 + 配置可一键重建（不直接传大文件）；
- 含数据卡（data card）：来源、许可、生成参数、统计摘要、各档样本数。

## 6. 阶段三：四类检测方法实现（约 6–8 周）

### 6.1 统一接口

每个方法实现为：
```
score(x) -> float       # 样本级：输入一条记录，返回合成概率分数
predict(C) -> float     # 语料级：输入混合数据集，返回估计占比 p̂
```
输入输出口径一致，才能公平对比。

### 6.2 四类方法

| 方法 | 核心思路 | 关键实现点 | 训练需求 | 与组内衔接 |
|------|---------|----------|---------|-----------|
| **① 统计分布漂移** | 真实 / 合成在特征分布上有差异 | 逐特征做 KS 检验（数值型）/ 卡方检验（类别型）；聚合为综合分数。语料级：用 MMD（RBF 核）度量全局分布距离，在已知 p 的校准集上拟合"MMD → p"映射 | 无（零样本） | 延续组内 AdaSCE 的分布漂移检测思路 |
| **② 密度似然阈值** | 合成数据在生成模型下似然偏高 | 用 CTGAN/TVAE 的判别器输出或重构误差作为分数。训练一个密度估计器（如 GMM / KDE），比较真实 vs 合成的似然 | 需访问生成模型或训练密度估计器 | 直接利用生成模型本身 |
| **③ 训练式分类器** | 直接学"真 vs 合成"边界 | 微调 XGBoost / MLP / TabNet 做二分类；注意防过拟合到生成器特征（跨生成器实验会暴露） | 需训练 | 可用 TabClean 的表格预处理管线 |
| **④ LLM 赋能检测（特色）** | 用 LLM 语义推理判别记录是否"不像真实数据" | 设计 prompt：给 LLM 展示数据 schema + 若干真实样本 + 待测记录，让 LLM 推理判断。参考 ZeroED 的 prompt 设计范式 | 无（零样本 / few-shot） | **直接延伸 ZeroED 范式** |

### 6.3 方法④（LLM 赋能检测）的设计要点

这是本题与组内 LLM 赋能方向的核心连接点，需要特别关注：

**Prompt 设计思路**（参考 ZeroED）：
```
你是一个数据质量专家。以下是数据集 {dataset_name} 的 schema：
{schema_description}

以下是该数据集的若干真实记录示例：
{few_shot_real_samples}

请判断以下记录是否为合成（机器生成）数据，并给出理由：
{test_record}

输出格式：{"label": "real/synthetic", "confidence": 0-1, "reasoning": "..."}
```

**关键设计决策**：
- few-shot 样本数：测试 0/3/5/10 shot，做消融；
- LLM 选择：至少测 2 个（如 Qwen2.5-7B + Llama-3.1-8B），看跨模型一致性；
- 输出解析：LLM 输出可能不规范，需做后处理提取分数；
- 成本控制：先在小数据集上测试，确认有效后再扩大。

**为什么 LLM 可能有效**：LLM 在大规模语料上见过大量真实表格数据的描述（如统计年鉴、医疗报告），可能对"什么样的数值组合是真实的"有隐式先验。同时，LLM 生成数据可能有可被 LLM 自身识别的模式。这一假设需要实验验证——**负结果也是结果。**

### 6.4 比例估计（任务二）的简单可行做法

用方法①或②得到每条分数 → 在已知 $p$ 的校准集上拟合"分数分布 ↔ p"的映射：
- 混合比例回归（Mixture Proportion Regression）；
- 分位数匹配（Quantile Matching）；
- MMD-to-p 标定曲线。

**先做简单标定，跑通比花哨重要。**

## 7. 阶段四：实验与评测（约 4–6 周）

### 7.1 核心指标

| 任务 | 主指标 | 辅助指标 |
|------|--------|---------|
| 样本级检测 | AUROC | TPR@FPR=5%、F1、准确率、校准(ECE) |
| 比例估计 | MAE \|p̂ − p\|（多档平均） | 各档误差曲线、偏差方向 |
| 估值影响 | 估值偏差 ΔV(p)、下游效用变化 | Shapley 值分布偏移、因果图结构差异（加分项） |
| 效率 | 单条打分时延 / 吞吐 | 显存占用、是否需训练 |

### 7.2 必做实验

**实验一  主表：4 类方法 × 3 种生成方式 × 2 个数据集**

在样本级与比例估计两任务上的指标对比。生成统一格式的结果表。

**实验二  检测难度曲线**

指标随合成占比 $p$ 变化（尤其低占比 5–10% 是否还测得出，最有价值）。
- X 轴：$p \in \{0\%, 5\%, 10\%, 25\%, 50\%, 75\%, 100\%\}$
- Y 轴：AUROC / MAE
- 每条线一种方法

**实验三  泛化实验**

跨生成器（训练见 CTGAN，测试见 TVAE / LLM）和跨领域（训练用 Adult，测试用 Credit）。
- 看分类器是否"记住了生成器"而非"识别了合成性"。

**实验四  消融**

- 参考模型大小（方法①②）、LLM 型号与 few-shot 数量（方法④）、文本长度 / 特征数对结果的影响。

**实验五  估值影响分析（新增核心实验）**

这是本选题区别于纯检测工作的核心增量：

| 子实验 | 方法 | 预期观察 |
|--------|------|---------|
| 5a. 下游效用曲线 | 在 $D_{mixed}(p)$ 上训练下游分类器，在真实测试集上评估 | 性能随 $p$ 变化的曲线；找到"效用无损阈值" |
| 5b. Shapley 值偏移 | 计算各记录在 $D_{real}$ 和 $D_{mixed}(p)$ 中的 Shapley 值，比较分布 | 合成记录的 Shapley 值分布是否系统性偏低 / 偏高 |
| 5c. 估值偏差量化 | 定义 $V(D)$ = 下游模型在 $D$ 上训练后的测试集效用，计算 $\Delta V(p) = V(D_{mixed}(p)) - V(D_{real})$ | 量化"每 1% 合成污染带来多少效用损失" |
| 5d. 因果忠实性（加分项） | 用 PC / GES 算法分别从 $D_{real}$ 和 $D_{syn}$ 学因果图，比较结构差异（SHD、Precision、Recall） | 合成数据是否保持变量间因果关系？为"因果忠实的数据定价"提供实证 |

### 7.3 结论怎么写

明确指出：
1. 哪种方法在什么条件下最好；
2. 低占比 / 跨生成器场景谁失效；
3. 训练式与零样本 / LLM 检测的取舍；
4. 合成污染对数据估值的量化影响（每 1% 污染的效用损失 / Shapley 偏移）；
5. 合成数据是否保持因果结构（如做了加分项）。

**负结果也是结果。**

## 11. 常见坑与规避

### 11.1 数据泄漏（头号杀手）
- **问题**：真实数据与其合成版分到了不同集合却仍"同源"，导致虚高。
- **规避**：按源数据集划分、严查重叠。生成合成数据时用的真实数据，不能出现在测试集中。

### 11.2 "假合成"污染
- **问题**：CTGAN/TVAE 生成的数据质量过差（如类别值全错、数值越界），模型一眼识破，结论失真。
- **规避**：务必做质量过滤，用 SDMetrics 确认合成数据与真实数据的统计相似性在合理范围。

### 11.3 生成器耦合
- **问题**：分类器过拟合到 CTGAN 的特定生成痕迹（如某些属性的取值分布偏移），换 TVAE 就崩。
- **规避**：这正是跨生成器泛化实验要暴露的。务必做、别藏着。

### 11.4 LLM 检测的成本与一致性
- **问题**：LLM 推理慢、API 贵、输出格式不稳定。
- **规避**：先在小数据集上验证有效性；用开源小模型（7B 级）本地部署；输出做严格后处理；报告平均时延和成本。

### 11.5 估值实验的混淆因素
- **问题**：估值变化可能来自数据量增加而非合成污染本身（加了合成数据 = 数据变多了）。
- **规避**：设置对照实验——(a) 混入等量合成数据；(b) 混入等量真实数据（对照组）；两者的估值差异才是"合成污染"的净效应。

### 11.6 评测不公平
- **问题**：不同方法用了不同阈值 / 数据切分。
- **规避**：统一接口、统一切分、统一指标脚本。

### 11.7 只追新不夯实
- **问题**：本题价值在"扎实、公平、可复现"。宁可少做一个花哨方法，也要把基准和对比做干净。
