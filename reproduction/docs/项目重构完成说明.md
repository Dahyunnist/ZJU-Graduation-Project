## 3. 本地smoke验证范围

本地smoke使用三个不同schema的确定性表和三种合成机制，覆盖P1--P4、0%/5%/10%/25%/50%污染率。它验证：

- 记录分区冻结且无泄漏；
- 检测得分只校准一次并被所有量化器复用；
- 污染bag成员比例精确；
- 同一证据行包含检测、比例、效用和决策字段；
- 伪影门禁能够保留并标记风险，而不是删除不利结果；
- smoke结果被标为 `formal_inclusion=false`。

smoke数值仅用于工程和逻辑核验，不能作为论文结论。

## 4. 正式运行前仍需完成

项目代码已经具备服务器执行入口，但正式实验不会在缺少数据时假装启动。当前剩余事项均属于正式数据与实验执行，不要求改动核心框架：

1. 在服务器按冻结配置实际训练CTGAN/TVAE并生成正式pool registry；
2. 根据GPU时间先运行单seed pilot，审计显存、时间和数值稳定性，再启动五seed正式矩阵；
3. 按最终论文外推范围，将三表启动矩阵通过注册表扩展到B-small/B-full，并优先补入TabDDPM、TabSyn等外部合成池；
4. 在不改变既有bag的前提下，将通过可靠性核验的新量化方法登记为增量比较项。

Flat Text、Datum-wise与Datum-wise+TA的正式结构和训练量级已与原论文核对并冻结；实现被标记为论文对齐自实现，而非论文原始数值复现。正式方法边界见 `configs/formal_method_registry.yaml`，导师构想的逐项验收见 `docs/导师建议覆盖与正式实现审计.md`。

正式配置的preflight在注册表缺失时返回 `passed=false` 和明确原因，不会训练模型。
