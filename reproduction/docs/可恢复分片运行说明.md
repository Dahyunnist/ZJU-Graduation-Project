# 治理实验的可恢复分片运行

治理实验以完整的 `governance_pilot.yaml` 或 `governance_formal.yaml` 为唯一实验契约。系统首先严格校验完整配置，再按“随机种子 × P1--P4 协议 × 合法检测器”生成确定性任务清单；分片不会放宽正式实验对五个种子、100 个 bag、两种污染机制、估值方法或 CUDA 环境的要求。

## 分片与恢复语义

- 每个分片写入 `output_dir/shards/<shard_id>/attempts/<attempt_id>`，不同尝试互不覆盖。
- 只有分片全部产物成功写出后，系统才原子发布 `COMPLETE.json`；中断的尝试不会被误认为完成。
- 使用 `--resume` 时，已完成且配置哈希一致的分片会被跳过。配置发生变化时必须使用新的 `output_dir`，系统拒绝混合不同配置的结果。
- 每个“种子 × 协议”只指定一个估值拥有者，KNN-Shapley/Data-OOB 不会随检测器重复计算。
- 只有全部计划分片完成后才生成总证据表、Finding 表、置信区间和配对检验；部分结果不会被标记为正式完整结果。

## 本地命令

```bash
python -m tabpollution governance shard-plan --config configs/governance_pilot.yaml
python -m tabpollution governance shard-status --config configs/governance_pilot.yaml
python -m tabpollution governance sharded-run --config configs/governance_pilot.yaml --resume --max-shards 1
python -m tabpollution governance shard-aggregate --config configs/governance_pilot.yaml
```

`--max-shards 1` 表示本次最多推进一个未完成分片。重复执行同一命令即可续跑。完整矩阵完成时，`sharded-run` 会自动聚合；提前手工聚合只返回待完成清单，不会产出伪完整结果。

## 共享服务器入口

```bash
CONFIRM_SHARED_GPU=1 MAX_SHARDS=1 bash scripts/run_governance_pilot.sh
```

启动脚本仍执行显卡空闲门禁、单卡绑定、CPU 线程限制和运行中 PID 监视。默认每次只推进一个分片，以便在分片边界重新确认共享资源状态。发现其他 GPU 计算进程时，脚本只终止本次治理进程；下次启动会从最后一个已原子完成的分片之后继续。

正式矩阵使用相同机制：

```bash
CONFIRM_SHARED_GPU=1 MAX_SHARDS=1 bash scripts/run_governance_formal.sh
```

不得删除其他用户进程，不得修改系统 CUDA、驱动或全局环境，也不得把中断尝试目录手工改名为完成标记。

## 按种子的资源感知后台调度

在单张共享 GPU 服务器上，可将经典检测器和深度检测器分为两个互斥队列。CPU 队列只运行 Char 3-gram、C2ST-LR 和 C2ST-XGBoost，并设置 `CUDA_VISIBLE_DEVICES=""`；GPU 队列只运行深度模型，且任一时刻最多运行一个深度分片。两个队列仍从同一个冻结配置派生分片，不改变模型、数据、随机种子、bag 或统计契约。

前台验证命令为：

```bash
CONFIRM_SHARED_GPU=1 SEED=2027 bash scripts/run_governance_seed_parallel.sh
```

正式长任务使用 `nohup` 或等价的作业托管方式启动，并将标准输出写入 `output_dir/scheduler/seed-<seed>-launcher.log`。调度器具有以下保护：

- `formal_scheduler.lock` 防止资源感知调度器与传统正式入口重叠；
- `cpu-worker.lock` 防止经典方法队列重复启动；
- GPU 队列在每个分片前重新检查显存、利用率和计算进程；
- 其他用户 GPU 进程出现时，只终止本项目当前 GPU 分片并等待，不操作外部进程；
- 分片只在完整产物写出后发布 `COMPLETE.json`，中断后从原子完成边界恢复；
- CPU 与 GPU 队列日志分别写入 `seed-<seed>-cpu.log` 和 `seed-<seed>-gpu.log`。

若主调度器的 CPU 子队列需要独立恢复，可运行：

```bash
SEED=2027 bash scripts/run_governance_cpu_queue.sh
```

该入口使用独立 CPU 锁，不会接管或干扰正在运行的 GPU 队列。首次使用资源感知调度时应先完成一个种子的验收，再将同一策略用于后续种子。
