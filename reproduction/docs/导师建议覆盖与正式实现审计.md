# 导师建议覆盖与正式实现审计

## 1. 验收结论

统一治理代码以“检测误差如何传导为污染率误差，并进一步影响下游任务决策”为唯一实验主线。smoke仅验证接口；pilot与formal使用真实注册表、正式算法尺寸和相同协议。正式配置设有硬门禁，不能通过减少种子、删除追加污染、关闭估值或启用未核实的旧近似方法伪装成formal。

## 3. P1–P4的正式含义

- P1：同表、同生成器、记录互斥，作为同分布上限。
- P2：同表、生成器互斥，测量未知生成器迁移。
- P3：训练表与测试表互斥，测量未知schema迁移。
- P4：表集合和生成器集合均互斥，测量完全迁移。

固定schema C2ST只进入P1/P2；跨表字符和Datum-wise方法进入P1–P4。Datum-wise+TA只在至少两张训练表时解释其table adaptation效果。

## 4. 方法真实性边界

正式方法状态由`configs/formal_method_registry.yaml`冻结。官方代码不可得的直接方法采用论文对齐自实现，并明确记录结构、差异和版本；不得声称复现论文原始数值。旧`table_transformer`只是早期近似，正式配置会拒绝它；正式矩阵使用名称明确的`column_positional_ablation`，不冒充IDA论文的列预处理基线。

## 5. 数据规模边界

当前冻结启动矩阵使用Adult、Abalone、Credit三个不同领域表及CTGAN、TVAE两个生成器，足以执行P1–P4的最小完整协议。数据注册表支持在不修改算法代码的情况下增加表和TabDDPM、TabSyn等外部合成池；扩展数据属于正式实验矩阵扩充，而不是框架代码迭代。论文结论必须按实际纳入的表/生成器限定外推范围。
