# 服务器运行手册

本手册用于代码在本地验证并推送后，在课题组共享服务器上启动实验。它不授权修改系统环境或占用其他用户资源。

## 1. 固定位置

```text
/mnt/nfs/bkbs/projects/ZJU-Graduation-Project       代码
/mnt/nfs/bkbs/datasets/ZJU-Graduation-Project       数据
/mnt/nfs/bkbs/results/ZJU-Graduation-Project        runs/outputs
/mnt/nfs/bkbs/checkpoints/ZJU-Graduation-Project    权重
/home/bkbs/miniforge3/envs/tabular-benchmark        主环境
```

仓库中的 `reproduction/data`、`runs`、`outputs` 和 `checkpoints` 应保持为上述NFS位置的符号链接。

## 2. 拉取与安装

```bash
cd /mnt/nfs/bkbs/projects/ZJU-Graduation-Project
git status --short --branch
git pull --ff-only

source /home/bkbs/miniforge3/etc/profile.d/conda.sh
conda activate tabular-benchmark
cd reproduction
python -m pip install -e ".[formal,test]"
```

不得使用 `sudo`，不得修改系统CUDA、驱动或其他用户环境。

## 3. 数据准备门禁

首次运行先从UCI官方地址准备三张真实表；该步骤只使用CPU和个人NFS目录：

```bash
python -m tabpollution governance source-prepare --config configs/governance_pool_build.yaml
```

随后检查真实表schema、二分类目标和生成器依赖：

```bash
python -m tabpollution governance pool-preflight --config configs/governance_pool_build.yaml
```

首次使用共享GPU前，先运行隔离的资源pilot。它只使用Adult、CTGAN/TVAE各10 epochs和2,000条合成记录，输出位于`data/governance-pilot`，不会生成正式注册表。脚本会在启动前拒绝非空闲GPU，并在运行中检测到其他计算进程时终止自身：

```bash
nvidia-smi
CONFIRM_SHARED_GPU=1 GPU_INDEX=0 bash scripts/run_governance_pool_pilot.sh
```

只有资源pilot完成、显存与耗时可接受且再次确认共享卡可用后，才能构建正式CTGAN/TVAE合成池：

```bash
CONFIRM_SHARED_GPU=1 bash scripts/run_governance_pool_build.sh
```

正式脚本会幂等地再次执行数据源准备；已存在且哈希不变的原始文件会保留首次获取日期。Adult、Credit、Abalone的下载哈希和规范表哈希记录在 `manifests/governance-pools-v1/source_prepare_summary.json`。合成池构建时，生成器源训练记录与后续评测真实记录按冻结种子互斥划分；不得手工合并这两个目录。正式池脚本与资源pilot采用相同的单卡空闲门禁和运行中监测：若其他计算进程出现，只终止本用户当前可恢复的池构建。

构建器将在个人NFS数据目录创建：

```text
/mnt/nfs/bkbs/datasets/ZJU-Graduation-Project/governance/pool_registry.csv
```

然后运行治理实验门禁：

```bash
python -m tabpollution governance preflight --config configs/governance_formal.yaml
```

只有输出 `passed: true` 才可进入训练。缺文件、schema不一致、目标列缺失或协议资源不全时必须停止。

## 4. 共享资源检查

每次启动GPU任务前执行：

```bash
nvidia-smi
```

确认显存、利用率和正在运行的用户任务。不得终止非 `bkbs` 进程。pilot和正式脚本默认拒绝启动，只有人工确认共享GPU可用后才设置。首先运行单种子pilot：

完整治理pilot前先测量一个正式尺寸Flat Transformer的耗时与峰值显存；该probe仅运行P1、单seed、单检测器，并写入独立的非正式结果目录：

```bash
CONFIRM_SHARED_GPU=1 GPU_INDEX=0 bash scripts/run_governance_resource_probe.sh
```

根据`runs/governance-resource-probe-v1/gpu_metrics.csv`与`resource_probe_status.json`确认资源预算后，再运行单种子pilot：

```bash
CONFIRM_SHARED_GPU=1 bash scripts/run_governance_pilot.sh
```

pilot完成且产物核验通过后，才运行五种子正式矩阵：

```bash
CONFIRM_SHARED_GPU=1 bash scripts/run_governance_formal.sh
```

脚本将CPU线程限制为正式配置要求，不使用 `n_jobs=-1`。治理pilot和formal也会在启动前检查指定GPU，并在运行中发现其他计算PID时终止自身。当前治理formal是单次完整矩阵，在实现细粒度断点续跑前，只能在确认有完整连续时间窗口后启动。

## 5. 长任务

数小时任务应在 `tmux` 中运行，并保留终端日志：

```bash
tmux new -s governance
CONFIRM_SHARED_GPU=1 bash scripts/run_governance_formal.sh 2>&1 | tee runs/governance-formal-v2-calibration/console.log
```

不得在不理解影响范围时使用 `kill`、`pkill`、`rm -rf`、`chmod -R`或`chown -R`。

## 6. 同步原则

源代码、配置、小型CSV汇总和论文图通过Git同步；数据集、模型权重、完整runs和缓存保留在NFS。服务器修改代码后先提交推送，本地再 `git pull --ff-only`，避免双端同时保留未提交修改。
