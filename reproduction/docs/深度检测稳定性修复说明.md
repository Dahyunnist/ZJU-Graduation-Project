# 深度检测稳定性修复与重跑准入规则

## 1. 问题性质

`governance-pilot-v1` 虽然完成了全部 22 个分片，但事后质量审计发现，Flat Transformer、列位置消融、Datum-wise Transformer 和 Datum-wise + TA 的原始检测分数均退化为常数。其检测 AUROC 为 0.5，且 ACC、PACC、Median Sweep 和 KDEy 等依赖混淆矩阵或分数分布的污染率估计产生非有限结果。因此，该轮深度检测结果只能作为失败诊断证据，不能进入研究结论、方法排序或正式论文表格；同轮经典算法的结果仍可复用。

## 2. 修复内容

深度检测训练现采用显式、可冻结的训练配置，包括学习率、权重衰减、梯度裁剪、最少训练轮数和早停耐心值。每一轮均在独立验证集上记录损失、AUROC、分数极差、梯度范数和学习率，并保存验证表现最优的模型状态，训练结束后恢复该状态。所有诊断均写入 `detector_diagnostics.json` 和模型 provenance，以便追溯。

流水线在发布完成标记前执行硬性质量门控。只要深度检测验证分数包含非有限值、分数极差小于 `1e-8`，或验证 AUROC 低于 0.52，该分片立即失败且不会生成 `COMPLETE.json`。聚合阶段另检查主污染率估计器 PACC 是否存在失败记录；存在失败时，结果标记为 `complete_with_method_failures` 且 `analysis_ready=false`。

## 3. 分阶段重跑策略

第一阶段仅运行 `governance_deep_stability_probe.yaml`：使用 P1、Adult、CTGAN 和 Flat Transformer，保留正式模型宽度与深度，但只训练 8 轮并使用两个低污染率测试袋。该探针用于验证优化设置，不作为论文结果。

探针需同时满足以下条件后，方可重跑正式 pilot 的深度分片：

1. 原始验证分数极差不小于 `1e-8`；
2. 原始验证 AUROC 不低于 0.52，且不再呈现随机常数输出；
3. PACC 的全部测试记录状态为 `ok`，估计值及误差均为有限数；
4. 运行过程未触发共享 GPU 保护机制。

第二阶段在原 `governance-pilot-v1` 输出目录中恢复运行。配置哈希变化后，分片调度器只复用与深度训练配置无关且已验证完成的经典检测分片，强制重新运行全部深度检测分片。只有所有分片完成并重新聚合、主估计器零失败后，pilot 才可被标记为可分析。

## 4. 共享 GPU 约束

稳定性探针和正式重跑均由专用脚本启动。脚本在启动前检查显存、利用率及计算进程；若显卡非空闲则拒绝启动。运行期间每 10 秒检查一次计算进程，如发现其他用户进程进入同一张卡，仅终止本项目当前进程，不处理任何外部进程。CPU 线程限制为 4，并以较低调度优先级运行。
