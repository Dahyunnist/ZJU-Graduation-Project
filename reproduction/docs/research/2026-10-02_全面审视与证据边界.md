# 研究工作全面审视与证据边界

审计日期：2026-10-02。历史代码基点：`418e6abdf6962d88d8c2c33bba79eec9c0518b08`。

这是科研有效性审计，不是对过去工作全盘否定，也不是新实验完成报告。依据包括冻结配置、关键实现、算法范围声明、五种子完成清单、正式结果报告及当前一手文献。此次未重新计算全部 386 万行证据、未重新训练模型；因此将“代码确认的问题”“旧报告的观察”“需要原始数据复核的影响大小”分开陈述。

## 1. 最重要的判断

已有工作完成了从零到可重复运行的实验链：数据池、跨域检测、校准、比例估计、治理动作、下游训练及统计汇总。这是有价值的研究基础。现在的问题是，**实验矩阵的宽度和工程规模大于支持研究机制的证据深度**。

三个层次不应继续平行扩张。更值得研究的问题是：合成数据改变了哪些与学习有关的结构；检测和校准驱动的筛选又改变了哪些训练样本；这些变化为什么对不同模型、不同群体产生不同影响。

过去的结果可以支持“值得继续研究的现象”，但不足以声称已经解释完整因果链、复现所有原论文性能，或得到普遍适用的污染治理规律。

## 2. 六点意见与当前差距

| 导师意见 | 已有基础 | 真正缺口 | 改进方向 |
|---|---|---|---|
| 目标与发现太散 | 四协议、多个方法、效用曲线 | 缺少一个预先定义的最终风险与决策目标 | 以“来源清理何时帮助/损害下游学习”为主问题 |
| 三层影响不清楚 | 同 bag、同检测得分、误差分解 | 统计恒等式不是机制；比例误差和效用之间不是必然单调关系 | 干预校准/阈值/动作，记录保留集合及模型变化 |
| 校准值得研究 | source、anchor、oracle 三策略 | 当前 anchor 主要改阈值，不能当作全面的概率校准研究 | 分离概率校准、阈值迁移、类条件分布漂移 |
| 深挖第三层 | LR-AUROC、两种混合方式、两种估值 | 模型/任务单一，对照不充分，细粒度结构和群体结果不足 | 配对预算对照、多模型、条件结构和尾部风险 |
| 升级 benchmark | 配置、CLI、分片、测试、审计 | 通用接口、可重评分缓存、数据代表性、失败规范及外部可用性不足 | 小而完整的机制评测任务集合，而非无限全排列 |
| study 作为后备 | 可复用生成池及训练链 | 缺少可证伪的集中假设和外部确认 | 先确保一个解释充分的 study，再决定 benchmark 投稿定位 |

“前两层价值有限”是当前研究策略判断，不是说检测与量化领域没有研究价值。这里把它们作为控制良好的测量工具，避免同时承担三条创新主线。

## 3. 各环节审视

### 3.1 文献搜集

已有综述覆盖直接检测、经典量化、数据估值和模型坍塌，作为入门地图有用。但不能将它们混为同类对比算法：来源识别、异常检测、生成质量评估、任务数据估值解决不同问题。ZeroED 检查表格错误，不是合成来源真值检测器；模型坍塌研究常涉及递归生成，不等于一次混合训练。

新方向需要补充：条件/结构保真度、数据中心式合成增强、目标任务风险、群体与尾部误差、筛选策略的选择偏差，以及校准方法评测。2026 年的 TabStruct、CalArena、TabQueryBench 等工作意味着“检测分数不等于质量”或“全局指标遗漏局部结构”已不是可以直接宣称的新发现。

应维护一张证据表：研究问题、直接/间接相关性、版本关系、正式发表状态、代码链接及 commit、已读范围、可复用组件、与拟议贡献重叠处。预印本和最终发表版本去重；搜索未找到代码不等于不存在；检索到论文不等于完成精读。

### 3.2 文献综述

旧综述按三条任务线组织，在当时是合理响应；现在继续堆算法会加重主线分散。建议改成“合成数据如何影响学习—现有指标为何不充分—来源治理如何介入—现有基准缺少何种决策证据”的问题导向结构。

每个关键方法解释输入、所估计的量、关键假设、输出如何影响决策、不能解释什么。保留检测与量化基础，但缩短与核心假设无关的历史铺陈。研究假设、旧实验事实、未来计划用明确不同的时态，不把探索预期写成已知 finding。

### 3.3 算法复现与忠实度

已有 `reports/code_availability_audit.md` 和 `algorithm_runthrough/paper_vs_local_scope.md` 明确写过 paper-aligned reimplementation，这一点应继续保持。正式矩阵增大网络并不自动消除与论文语料、分词、参数搜索及协议的差距。

| 组件 | 可以确认的成果 | 不能直接声称的成果 | 下一步 |
|---|---|---|---|
| char3gram、flat/datum/TA 等检测实现 | 本地实现进入历史正式矩阵 | 全部使用作者代码、达到论文 SOTA 数值 | 给每一实现建立配置/论文条款差异卡；官方代码复查 |
| C2ST-LR/XGB | 经典真假判别参照 | 跨不同 schema 无需适配可直接使用 | 明确适用协议与特征空间 |
| CC/PCC/ACC/PACC | 公式实现及 QuaPy 小向量核验 | 全部量化算法均与官方包一致 | 扩展真实分数与退化输入的契约测试 |
| HDy/DyS/KDEy 等 | 自实现可以运行并记录失败 | 原方法所有距离、超参、调参过程完全复现 | 对照官方实现、标注变体、固定带宽/分箱规则 |
| KNN-Shapley | 小规模穷举核验递推 | 测得 LR 或任意模型的真实 Shapley 值 | 当作 KNN 效用下代理值，不替代模型重训练效应 |
| Data-OOB | bagging OOB 分数闭环 | 与有符号 Shapley 值在零点上同义 | 分开解释和统计，不跨方法比较“负价值率” |

代码中 `_distribution_match` 对非 Hellinger 分支采用绝对差之和，`dys` 传入 `tops` 名称也走这一分支；这应标为当前距离变体，不能用名称暗示完全复现论文方法。`quapy_formula_crosscheck` 只核验四个基本方法，并非九种量化器整体官方复现。KDEy 的 scipy KDE 默认带宽也须写清。

不建议现在把所有算法重新实现一遍。先选择一个足够可靠的检测器和 CC/PACC 两类量化参照，完成机制试验；其余方法保留用于稳健性，避免复现工作再次压过研究问题。

### 3.4 框架与数据

现有工程具有数据登记、冻结配置、分片、断点续跑、失败记录和 CPU smoke，这是可以继承的优势。当前目录本来已有标准 `src` 包结构，根目录混入论文不是算法架构必须重写的理由。

正式配置包含 Adult、Abalone、Credit，但下游目标表实际只有 Adult 和 Credit：P1/P2 测 Adult，P3/P4 测 Credit。不能表述成“三个独立目标域的下游验证”，更不能把 110 个分片当作 110 个独立数据集。

生成池固定生成种子与后续五个评估种子不同。五种子覆盖部分划分/训练/抽样随机性，不等于五次独立重训生成器。不同表规模、难度、schema 与协议同时变化，P1 对比 P3 不是只改变“跨表”这一个因素的因果对照。

`record_id` 的构造未包含生成器名。当前复合主键含 test_generator，已有结果不能据此直接判为冲突，但未来统一跨生成器样本注册必须包含生成器、池版本和内容摘要。数据划分还应避免依赖表在配置中的枚举位置产生随机种子差异。

### 3.5 正式实验完成与研究完成

旧完整性报告登记 110/110 分片、3,861,000 条 evidence、520,000 条 valuation，118,300 条量化失败证据行、91 个聚合失败条件。这是完成覆盖和记录规模，不是独立统计样本数；同 bag 的同一效用会随检测器/策略/量化器重复出现。

既有 Holm 检验可以减少所定义比较族的多重检验问题，但不能修复伪重复、事后挑选假设或只有两个目标表的问题。种子级 CI 也不代表跨数据集泛化区间。

下表给出代码定位（函数/关键变量比易变行号更稳定）。P0 表示在进一步据此下结论前处理，不表示必须马上重新训练全部历史矩阵。

| 优先级 | 代码证据 | 问题与影响 | 处理方式 |
|---|---|---|---|
| P0 | `governance/formal_analysis.py: low = ...true_prevalence.isin([.05,.10])` | append 实际比例因整数取整不等于名义 .05/.10，低比例表会漏掉它们 | 用名义比例选择实验条件，实际比例计算误差；新分析版本重汇总 |
| P0 | 同文件 `valid`、`primary_rows` | 效用曲线取成功 PACC 行；不依赖量化器的 keep 效用也受到筛选，且被重复加权 | 按唯一基础 bag 去重；分离动作效用、策略效用和量化成功率 |
| P0 | `pipeline.py: clean_train = ...bag_seed + 71` | clean 基线与 bag 中真实行不是相同抽样，差异混入样本组成波动 | 新设计使用共享真实核心、配对替换索引和预算匹配对照 |
| P0 | `pipeline.py: estimated_decision`, `_safe_max` | 量化失败在原始决策变为不清理；无效清理的 NaN 被候选最大值忽略 | 显式失败/弃权/安全回退；报告覆盖率和含成本效用，不能仅成功条件平均 |

| P1 | `pipeline.py: predict_prevalence(...)["clipped"]` | 只保留截断值，范围审计不能发现原始估计越界和饱和 | 新版存 raw、clipped、out_of_range、分母和失败诊断 |
| P1 | `_PlattCalibrator`、校准策略构建 | source 和 real_anchor 概率映射相同，anchor 改阈值；不能称为目标概率校准 | 拆成 score_calibration 与 threshold_policy 两因素 |
| P1 | 检测验证集的多重用途 | 早停、Platt、阈值、量化类条件统计复用验证数据 | 增设独立 calibration/decision validation 或交叉拟合 |
| P1 | `_utility` | 下游主要只有 Logistic Regression 的 AUROC | 至少增加树模型；主指标 proper loss，辅以排序和群体/尾部指标 |
| P1 | `_valuation_rows(...pure_test...)` | KNN 估值使用测试标签进行诊断，若进一步据此选择训练样本就发生选择泄漏 | value-validation 与最终 test 分开，旧结果限定为事后诊断 |
| P1 | formal analysis 的负值率 | Data-OOB 正确性分数不以负值表达有害；NaN 比较为 False | 方法分别解释，有限值分母及缺失覆盖率单独报告 |
| P1 | `pipeline.py` 中瞬时 raw_bag_scores | 未看到治理主循环调用 detector.save 或持久化完整逐样本预测 | 先盘点服务器实际缓存；若无，不假定可以免费离线重校准 |
| P2 | 软件依赖主要为版本区间 | 后续安装可能与历史环境不同 | 发布锁文件/环境快照，并保留原环境，不盲目升级 |

具体数值例子：真实基数 1000 时，append 名义 5% 生成 53 条合成数据，共 1053 条，实际比例为 53/1053；名义 75% 为 3000 条合成，共 4000 条。因此“每个 bag 都是 1000 条”不准确。如果池比抽样规模小，`sample_rows` 会有放回抽样；需报告重复率和有效独立样本量。

这些问题有的影响已有汇总数值，有的只限制解释。不能把全部旧结果作废，也不能在未重算前保证修正后方向完全不变。

## 5. 对已有 finding 的重新定级

| 旧观察 | 目前可用的解释 | 不应继续使用的强表述 |
|---|---|---|
| 同表与跨表检测性能差异 | 在指定 Adult→Credit 及生成器组合中存在迁移困难 | 已证明所有表格的通用跨表规律 |
| 格式审计未超过门限 | 所测简单格式特征没有触发所设门禁 | 数据完全没有伪影 |
| 低比例估计误差大 | 特定跨表得分漂移值得追查，须修正 append 漏选 | 全部低比例模式均已被完整比较 |
| anchor 降低 FPR，而 PACC 相同 | 阈值控制与软分数量化分离；后者不变在此实现中是预期 | 新发现某概率校准无效，或量化器不可改善 |
| append 平均 +0.0009、replace -0.0027 | 历史特定 LR-AUROC 与当前汇总口径下的描述值 | 合成增强普遍有益、替换普遍有害 |
| 可检测性与效用不一致 | 两者定义不同，现有散点是候选线索 | 已建立不相关定律或解释了损害原因 |
| 分解残差约 2.22e-16 | 程序实现的恒等式闭合检查通过 | 已证实三层因果传导模型 |
| 多项配对检验显著 | 在规定样本与比较族下发现差异 | 显著差异等于实质价值或新颖机制 |

误差分解的真实口径如下。令 π 为 bag 实际合成比例，q_ref=π·TPR+(1−π)·FPR（TPR/FPR 来自参考测试集），q_bag 为 bag 预测阳性比例，则：

```text
估计比例 − π
= (q_ref − π) + (q_bag − q_ref) + (估计比例 − q_bag)
    参考运行点偏差    bag 与参考的偏差      量化器修正
```

中项不是简单的“实际比例减名义比例”。该式通过加减同样的量必然成立；各项可用于定位，但要谈机制，还需改变某一环节并观察后续动作及损失是否随之改变。

## 6. 三层的统一认识

有两条必须分开的路径：

```text
生成过程 → 标签/条件结构/尾部覆盖偏差 → 混合训练集 → 下游模型风险
                           ↑                 ↑
检测器 → 概率校准/阈值 → 比例估计 → 治理动作 → 保留样本集合
```

未经治理的数据效用不会因为量化器名称改变而改变。量化误差只有改变决策，或进一步改变删样本预算/权重，才可能影响下游。即使比例估计更准确，清理策略本身错误仍可能降低效用；反之，来源不完全可辨识的数据也可能对目标任务有用。

概率校准改善 proper loss 不必然改变排序。严格递增映射并同步变换阈值会保持删除集合不变；这应作为负对照。当前 Platt 系数没有正约束，不能无条件宣称所有拟合映射都保序。

真正需要解释的是：**删掉了谁、保留了谁、训练规模变了多少、标签条件结构与稀有群体覆盖怎样改变，哪类模型因此受益或受损。**

## 7. 行动结论

先做一次不训练的分析口径修复与缓存盘点，再用小矩阵开展有控制的第三层探索。暂不扩成九种量化器×所有检测器×所有新指标的大矩阵。主线以 study 成立为底线，benchmark 以可复用协议和外部可运行性为加分项，而不是反过来以代码规模证明论文价值。

本次审计没有为旧实验补造结果。下一阶段所有新数值、口径修正和论文结论都应在独立输出版本中生成，保留本文件作为问题登记。
