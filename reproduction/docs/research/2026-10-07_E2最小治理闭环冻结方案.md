# E2：来源校准如何传导至治理动作和任务风险——最小闭环

日期：2026-10-07。本批为**机制探索**，不是重新跑一遍三任务排行榜。固定 Adult 同表跨生成器 P2（来源 CTGAN，目标 TVAE）、一个经典 C2ST-LR 检测器、3 个划分种子、替换式 1000 行 bag、污染比例 5%/10%/25%、每比例两个 bag。固定 downstream LR、PACC 主量化器（PCC 仅作敏感性对照）、10% 治理触发门槛。先不扩跨表深度模型或 GPU。

## 信息边界

真实和合成池在每个种子按现有协议拆成 source、detector_train、detector_val、downstream_train、final_test。检测器在来源 CTGAN 的 detector_train 训练，detector_val 再拆成互不相交的调参半与概率校准半。目标 TVAE 的 detector_val 只供**oracle_target** 诊断用，不允许混入可部署政策。目标真实 source 区段划 500 行给真实锚点阈值，另 500 行给下游任务概率校准，两者互不重叠。bag 只来自 downstream_train，最终任务风险只用真实 final_test。记录各集合 ID 和源数据哈希；不根据 final_test 选择校准器或阈值。

## 三种来源校准政策与动作

1. `source_only`：来源检测验证集拟合单调 Platt，并在该集选 FPR 5% 阈值，可部署但可能迁移失败。
2. `target_real_anchor`：保留同一来源 Platt 映射，只用 500 条目标真实锚点迁移 FPR 阈值；可部署但不可能凭干净负例推断完整目标概率映射。PACC 的来源参考统计仍沿用 source_only。
3. `oracle_target`：用目标真实+合成验证标签拟合目标 Platt 和参考统计，仅用于识别信息差距，**不可部署**。

每个 bag 首先固定删除数为 50：原始检测分数、单调校准分数的 top-50 应选中同一批记录，作为代码负对照；另有同数随机删除和知道真实来源后的来源 oracle 删除。随后每项政策以 PACC 估计是否达到 10% 门槛；达到才按其 FPR 阈值清理。对**实际删除数**另做等量随机、来源 oracle 对照，防止把“删得更多”误说成“排序更好”。所有动作都与完全保留比较。

每个动作报告删除数、删除合成精度、被保留类别比例与预定 age 尾部比例；下游真实测试同时报告 AUROC、AUPRC、Brier、log loss、正类 log loss，并额外给出仅由独立真实任务校准集拟合的下游校准后读数。必须区分来源校准与下游任务校准。若清理后只剩单类或 PACC 分母退化，明确记录失败，不用默认值伪装成功。所有任务模型设置、数据预算与测试池一致。

## 判别规则与边界

- 首先通过固定 top-50 集合不变性；若失败，先修实现或标注单调性/数值并列边界，不解释下游结果。
- 观察校准政策是否改变 PACC、触发率、删除数和删除集合；再与等量随机/来源 oracle 的下游风险相比。来源 oracle 只知道真实/合成身份，**不是任务最优删除上界**。
- 若校准只改变阈值但 PACC 不变，应和原正式实验结论一致；重点观察这种变化是否真正影响任务风险，而非重复报告 FPR。
- 本批仅 Adult/CTGAN→TVAE 且仍来自固定生成池；即使出现清晰机制，也需要独立池、跨表 P3/P4 和其他任务模型作后续确认。旧正式实验已报告校准与 PACC 的分离，本批新意必须来自**删样本集合与任务风险的可核查传导**，不能把已知的校准现象再包装成新 finding。

每种子原子写一个分片，后台单进程低优先级 CPU 执行；完成分片、每 bag 预测与动作记录、训练模型、校准器和失败状态单独保存，便于中断后续跑与独立审计。
