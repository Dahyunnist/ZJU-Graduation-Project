# E0 历史证据核验与重分析报告

日期：2026-10-06。分析版本：`e0-20261006-v1`。对象：`governance-formal-v2-calibration` 的 110 个已完成分片。历史代码基点：`5f9a7a6`（本轮没有修改历史采样、训练或评分实现）。

## 一、结论先说

E0 已完成：完整读取并核验选定分片，修复低比例条件筛选和效用去重口径，分开统计量化失败与清理不可用，盘点缓存，并重建已评估 bag 的抽样进行检查。原始输入、旧 Excel 和旧分析目录没有被覆盖；没有训练模型、没有使用 GPU。

旧实验没有整体失效。低比例追加模式确实被漏选，已补入；修正后的总体效用均值与旧描述接近。但“零污染也有非零差值”和“跨表来源清理大量不可用”说明，下一阶段必须先建立配对对照、明确失败结果，再讨论合成数据的作用机制。

目前足以进入小规模 E1 机制探索，但不适合立即扩展或重跑旧大矩阵。E0 完成不等于历史实验的所有设计缺陷已被修复。

## 二、本次实际做了什么

1. 以原 `completed_shards_manifest.json` 指定的 attempt 为准，逐个读取 110 个分片，而不是混入失败尝试或重复执行。
2. 核对全部 3,861,000 行 evidence 和 520,000 行 valuation。对选定 evidence 文件读取前后校验 SHA256，并记录输入路径、大小、哈希和分析程序哈希。
3. 核验分片集合与冻结 shard plan 一致；每个量化条件有 100 个 bag，其中 5 个安排下游效用评估。
4. 低比例筛选改为名义比例 5%/10%，估计误差仍使用实际比例。
5. 从重复证据中提取 26,000 个基础 bag，其中 1,300 个计算过效用；单独提取 21,450 个“bag×检测器×策略”的已评估清理动作。
6. 重复值必须一致才去重。检查数值冲突与“同 key 部分缺失、部分有值”冲突，未发现冲突；没有盲目取第一行。
7. 对 1,300 个已评估 bag 重放确定性抽样，检查规模、来源比例、重复索引、真实训练/测试交叉及零污染对照。
8. 盘点正式运行目录及登记 checkpoint 目录。输出独立 CSV/JSON 和本报告，不修改旧 Excel。

主分析使用单线程、低优先级 CPU，并禁用 CUDA。新增检查通过，本地全部单元测试为 119 passed；两个原有库警告不影响通过结果。

## 三、哪些旧结果变了

### 3.1 低比例追加模式原来完全漏选

原代码使用实际比例是否精确等于 0.05/0.10 进行筛选。真实基数 1000 时，追加模式的实际比例分别是 53/1053 和 111/1111，不恰好等于名义值。

| 范围：量化成功的低比例 evidence 行 | 旧筛选 | 新筛选 |
|---|---:|---:|
| 记录数 | 575,800 | 1,151,600 |
| 新补入的追加模式记录 | 0 | 575,800 |

这些是跨方法/策略重复的记录数，不是独立 bag 数。以下按 `source_only + PACC` 展示修正后的描述性 MAE，先在每个种子/检测器/名义比例内汇总，再对等规模条件平均：

| 协议 | 替换模式 MAE | 追加模式 MAE |
|---|---:|---:|
| P1 | 0.014021 | 0.013516 |
| P2 | 0.036019 | 0.035938 |
| P3 | 0.814196 | 0.813987 |
| P4 | 0.855968 | 0.855544 |

结论：漏选确实存在，但补入后，指定跨表条件下 PACC 误差大的现象仍存在。不能说所有量化器都达到这些数值，也不把结果推广到其他目标表。

### 3.2 去重和解除 PACC 成功筛选后，总体效用变化很小

效用为下游 LR 在纯真实测试集上的 AUROC。这里比较保留混合数据训练与旧干净参照的差，正值表示 AUROC 更高。

| 混合方式 | 旧成功 PACC 记录加权均值 | 新唯一基础 bag 均值 | 新减旧 |
|---|---:|---:|---:|
| replace | −0.00270521 | −0.00259824 | +0.00010696 |
| append | +0.00087673 | +0.00085527 | −0.00002146 |

旧计算分别重复使用 11,060/9,480 行，新计算分别使用 700/600 个基础 bag。旧列是对旧筛选规则的明确重算，不声称与旧 Excel 的每一个不同聚合层次都完全同义。

“追加略升、替换略降”的平均方向没有被推翻。但均值很小，且依然受非配对干净参照、不同预算含义、只有两个目标表及固定生成池等限制。本次不新增显著性宣称。

### 3.3 零污染对照确认存在抽样差异

200 个已评估的零污染协议/模式/bag 记录，其混合组与干净参照的效用差全部非零，最大绝对差为 **0.025032 AUROC**。

| 目标表 | 零污染差值均值 | 最小值 | 最大值 |
|---|---:|---:|---:|
| Adult | +0.001962 | −0.008437 | +0.013037 |
| Credit | −0.002794 | −0.025032 | +0.016300 |

追加/替换在 π=0 时使用同一个 bag，结果一致，因此这两行不能当独立重复。这里的 200 条也包含不同协议对相同条件的复用。

原因与代码吻合：干净参照使用另一抽样种子，未与混合组的真实样本完全配对。因此单个 bag 的小效应不能直接归因于合成数据。这不是一个普适“噪声下限”，也不能用减掉这个均值的方法假装修复设计；E1 应重新构造严格配对对照。

## 四、比总体均值更值得注意的现象

### 4.1 清理动作的可用性存在明显差异

21,450 个已评估清理动作中，2,127 个没有可定义的下游效用，占 **9.916%**。全部集中在 P3/P4 的 `source_only`：

| 协议与策略 | 已评估清理动作 | 可计算效用 | 不可计算效用 | 不可计算比例 |
|---|---:|---:|---:|---:|
| P3 source_only | 1,625 | 455 | 1,170 | 72.00% |
| P3 target_real_anchor | 1,625 | 1,625 | 0 | 0% |
| P4 source_only | 1,625 | 668 | 957 | 58.89% |
| P4 target_real_anchor | 1,625 | 1,625 | 0 | 0% |

旧实现对清理后少于 10 行或不能构成二分类训练/测试的情况返回 NaN。原输出没有保存每次清理的保留索引和具体失败原因，所以本次不把全部失败强行归因为“删空”或“只剩一个类别”。它们应明确报告为不可行动结果，不能当作 0 效用，也不能直接从比较分母消失。

### 4.2 锚点主要修复阈值与行动安全性，而不是 PACC 精度

按检测器/种子平均，P3/P4 来源阈值的目标 FPR 分别为 0.807372/0.892628；目标真实锚点策略下为 0.050164/0.048809。与此同时，各匹配条件下 source-only 与 anchor 的 PACC MAE 差最大值是 **0**，符合当前实现仅改阈值、不改软分数映射的预期。

只在两个策略都可计算效用的匹配动作上比较，anchor 相对 source-only 的清理后 AUROC 平均差为：P3 +0.019256（455 个动作），P4 +0.076048（668 个动作）。这是成功交集上的描述，不含 source-only 失败的 2,127 个动作，不能冒充全体策略的平均提升。

另一方面，anchor 清理相对“不清理”的平均收益只有 P3 +0.000678、P4 +0.000116。这两个事实并不矛盾：**避免严重误清理，不等于已经证明清理优于保留。**

这条区分是 E1/E2 值得优先探索的线索。下一阶段需要同预算随机删除、群体保留统计和更多下游模型，判断改善是否来自避免选择性误删，而不是现在就宣布新机制已经证实。

## 五、失败和缺失重新分类

| 类型 | 本次计数 | 如何解释 |
|---|---:|---|
| 未安排效用计算的基础 bag | 24,700 | 设计上每条件只评估前 5/100，不能称为运行失败 |
| 安排且 keep/clean 效用有效的基础 bag | 1,300 | 不以量化器成功与否筛选 |
| 真实来源 oracle 清理后为空 | 100 | 全合成条件，删除全部合成行后为空，是定义边界 |
| 量化失败 evidence 行 | 118,300 | 与旧完整性报告一致 |
| 细分到比例/模式的失败量化条件 | 1,183 | 合并比例/模式后是旧报告 91 个条件，不是多出新失败 |
| 安排效用时量化失败的策略记录 | 5,915 | 不能把旧隐式“不清理”回退当正常有效量化策略 |
| 有效量化但选中不可用清理动作的策略记录 | 19,143 | 对应 2,127 个动作被九种量化器重复引用，不是 19,143 个独立 bag |

之前审计提到的“候选清理无效但 regret 为零”属于代码可能产生的风险。本轮在所定义的已评估记录范围内计数为 **0**，因此不能继续把它当已经观察到的实验问题。真正观察到的是策略效用/遗憾缺失和成功条件统计的覆盖边界。

本次保留成功条件均值，同时给出总数、有效数和失败数；没有事后编造一个失败罚分来改变排名。成本及回退动作需要在下一轮预先规定。

## 六、数据与缓存检查

### 6.1 确定性抽样重建

对全部 1,300 个安排过效用评估的基础 bag，按冻结采样规则和登记数据池重建，规模及实际比例与保存值一致。

- 未发现 bag 内重复 record_id：本轮评估子集没有触发有放回采样。
- 未发现重建的真实训练行与真实测试行 ID 重叠。
- Adult 下游真实/合成池各 6,343 行，Credit 各 3,896 行；最大追加合成数为 3,000，未超过可用池。
- π=0 的追加/替换组对应效用完全相同。

这些是按当前未修改的历史实现重建的检查，不是原实验保存的逐行采样清单，也不代表检查了所有可能的数据泄漏或生成数据内容重复。

### 6.2 可以继续复用什么，缺什么

| 材料 | 盘点结果 | 后续意义 |
|---|---|---|
| 数据池及来源/任务标签 | 登记路径可用 | 可以复用并重建抽样 |
| 生成器 checkpoint | 找到正式 6 个及 pilot 2 个 | 不必仅为新增诊断重新训练生成器 |
| 聚合 evidence、估值、协议清单、诊断 | 可用 | 可以重算当前保存指标及分层统计 |
| 正式检测器 checkpoint | 在盘点的正式 run/checkpoint 路径未找到 | 不应假定可以直接恢复旧检测器 |
| 逐样本原始检测分数、校准分数 | 未找到完整缓存，诊断只有范围等摘要 | 无法仅凭汇总表重新比较校准器 |
| 清理保留索引/删除掩码 | 未找到 | 不能直接查清具体误删了谁 |
| 下游逐样本预测 | 未找到 | 不能从 AUROC 汇总逆推出 log loss、群体损失 |
| 量化原始未截断估计 | evidence 未保存 | 不能恢复真实越界率/截断率 |

501,047 条成功量化记录的保存估计恰为 0 或 1，占成功记录约 13.39%。这只能叫边界值比例，不能叫截断率，因为有的原始估计本来就在边界。

两类估值各 260,000 条均为有限值。Data-OOB 不再输出与 Shapley 同义的“负价值率”；KNN-Shapley 的负值率使用有限值作分母。本轮没有缺失估值被误当作非负值的实际案例。

## 七、旧结论的处置

| 旧结论/线索 | E0 后状态 |
|---|---|
| 特定跨表条件的检测/量化迁移困难 | 保留，追加低比例补入后仍成立 |
| 目标真实锚点能控制本轮目标 FPR | 保留为本轮观察，不扩大为无条件保证 |
| anchor 改善 PACC | 不成立；匹配误差完全相同，原代码也不应产生改变 |
| 追加略升、替换略降 | 保留为描述，不能写成普遍因果结论 |
| 误差分解接近机器精度闭合 | 独立重算残差约 4.44e-16，仍仅是恒等式校验 |
| 清理有益 | 必须拆成“防止严重误清理”和“超过不清理”，目前只前者有较强线索 |
| 所有旧算法与方法原论文等价 | 本次未验证，复现忠实度限制不变 |

## 八、下一步建议

先开展小规模配对机制实验，而不是整体重跑 110 分片：

1. 建立 π=0 完全一致的真实参照和同预算对照，以 log loss、AUROC 及少数群体指标观察数据影响。
2. 选择少量代表性检测器，新增 checkpoint、原始得分、删除索引和下游预测缓存；只在必要范围重新训练，不假装可从旧汇总恢复。
3. 重点比较“不清理、来源阈值清理、锚点阈值清理、同数量随机删除”，追查谁被误删及模型表现变化。

E0 的完成标准是证据口径清晰、已知边界可追溯，并选出值得验证的机制；不是事后把旧实验加工成因果研究。
